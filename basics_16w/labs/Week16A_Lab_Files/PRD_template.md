# PRD 한 장 — 화면을 만들기 전에 채웁니다

PRD(Product Requirements Document)는 **무엇을 만들지 만들기 전에 적어 두는 문서**입니다.
일곱 칸을 다 채우기 전에는 Claude에게 화면을 만들라고 하지 않습니다. 빈 칸이 많으면 업무를 더 작게 자릅니다.

| 칸 | 질문 | 내 답 |
|---|---|---|
| ① 목적 | 이 화면이 없어서 지금 무엇이 불편한가 · 끝나면 무엇이 달라지나 | |
| ② 사용자 | 누가 · 얼마나 자주 · 어떤 자리에서 여나 (팀장 회의 · 담당자 매일) | |
| ③ 입력 | 어떤 파일 · 시트 · 열을 읽나 · 자료 등급(공개 · 내부 · 비밀) · 기준일 | |
| ④ 핵심 기능 | 화면에서 할 수 있는 일 3개 이하 (보기 · 거르기 · 판정하기 …) | |
| ⑤ 판정 규칙 | 숫자가 어떤 조건이면 경고 · 차단하나 · 사람이 무엇을 누르나 | |
| ⑥ 성공 기준 | 무엇을 대조하면 '맞다'고 할 수 있나 (원자료 합계 · Excel 정답 · 표본 3건) | |
| ⑦ 제외 범위 | 이번 버전에서 **하지 않을** 것 (로그인 · 실시간 연동 · 메일 발송 …) | |

## 쓰는 순서
1. Claude Code에게 "PRD_template.md를 같이 채우자. 내 업무를 이해할 때까지 질문을 한 번에 하나씩 해 줘."
2. ⑥ 성공 기준이 **확인 가능한 문장**인지 따져 보게 합니다. "보기 좋다"는 성공 기준이 아닙니다.
3. ⑦ 제외 범위를 먼저 굳힙니다. MVP가 커지는 이유는 거의 언제나 여기가 비어서입니다.
4. 다 채운 PRD를 그대로 붙여 넣고 "이 PRD대로 한 파일 HTML을 만들어 줘"라고 합니다.

완성 예시: `answers/PRD_fund_dashboard.md` (대시보드) · `answers/PRD_capital_call_mvp.md` (업무 MVP)
